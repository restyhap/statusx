# 02 启动命令与当前运行方式

> 记录时间：2026-10-22
> 结论先说：**没有安装包、没有登录项、没有 run 脚本**，靠"手动打包 + 手动 nohup 跑二进制"维持运行。

## 1. 构建（唯一脚本）

```bash
cd /Users/resty/02-workspace/09-project/desktop-05-statusx
./scripts/build-app.sh
```

脚本做的事（`scripts/build-app.sh`）：

1. `swift build -c release`
2. `rm -rf build/StatusX.app` 后重建 `Contents/MacOS`、`Contents/Resources`
3. 拷 `.build/release/StatusX` → `build/StatusX.app/Contents/MacOS/StatusX`
4. 拷 `Packaging/Info.plist` → `build/StatusX.app/Contents/Info.plist`
5. `codesign --force --deep --sign -`（ad-hoc 签名，失败不中断）
6. 打印 `已生成：.../build/StatusX.app`

产物：`build/StatusX.app`（菜单栏应用，无 Dock 图标）。

## 2. 运行 / 停止

```bash
# 启动（当前就是用这条在跑）
nohup build/StatusX.app/Contents/MacOS/StatusX >/dev/null 2>&1 &

# 停止
pkill -f "StatusX.app/Contents/MacOS/StatusX"

# 换配置重启 = 停止 + 启动
pkill -f "StatusX.app/Contents/MacOS/StatusX"; sleep 1.2
nohup build/StatusX.app/Contents/MacOS/StatusX >/dev/null 2>&1 &
```

**为什么直接跑二进制而不是 `open build/StatusX.app`**：
直接跑会继承当前终端已拿到的辅助功能授权；`open` 启动的是独立进程，需要到
「系统设置 → 隐私与安全性 → 辅助功能」里单独勾选 StatusX，否则 AX 全部失败。

## 3. 探针工具（手工编译，不在 build-app.sh 里）

```bash
swiftc -O tools/mbtool.swift -o build/mbtool
swiftc -O tools/barcut.swift -o build/barcut
```

用法：

```bash
./build/mbtool scan                     # 列出所有状态栏项（x / 宽度 / App / bundle id）
./build/mbtool click 1509 13            # 在坐标处真实点击（点自己的状态项、点展开后的图标）
./build/barcut /tmp/shot.png 1100 2     # 截图列扫描：输出有内容像素的列区间，绕开折叠项假坐标
```

`barcut` 的存在原因：被折进 `<<` 的项，AX 返回的是系统伪造的帧（宽度和坐标都不可信），
只能靠截图逐列判断谁真的画在栏上。

## 4. 日志与配置

| 内容 | 路径 |
|---|---|

| 配置 | `~/Library/Application Support/StatusX/config.json` |
| 偏好域（`autosaveName=statusx`） | `~/Library/Preferences/StatusX.plist` |

`config.json` 字段：

| 字段 | 含义 | 当前值 |
|---|---|---|
| `bandWidth` | 状态项固定宽度 | 310 |
| `metrics` | 310px 带子里显示哪些指标：`cpu`/`memory`/`network`/`disk`/`battery`/`fan`；不写 = 全部 | 全部 |
| `metricValues` | 是否在图标旁显示数值 | true |

| `metricOrder` | 组件显示顺序（6 个组件，含未启用的），由设置页拖拽写入 | 默认顺序 |
| `panelBackground` | 面板背景：`popover`（正式版毛玻璃）／`white`（测试纯白） | white |
| `launchAtLogin` | 登录项回显（真实状态以 `SMAppService` 为准） | 自动写入 |
| `panelSort` | 面板列表排序：`name`／`position` | name |
| `showStatsCard` | 面板是否显示「菜单栏」统计卡 | true |
| `maxListRows` | 面板列表最多可见行数 | 14 |
| `panelWidth` | 面板宽度（320–420） | 340 |
| `language` | 界面语言：`en`/`zh-Hans`/`zh-Hant`/`ko`/`de`/`fr`/`es`/`pt`/`ru`；不写 = 跟随系统 | zh-Hans |
| `closeAction` | 关闭设置窗口时：`minimize`（留在菜单栏）／`quit`（退出） | minimize |

改配置必须重启进程生效；面板对象在第一次点击时才创建，所以背景改动同理。
例外：设置窗口里的改动即时生效（写盘 + 防抖 0.5s 重排），切语言会立即重建界面。

## 6. 现状与未完成

### 6.3 点击状态项 → 弹窗延迟（已改，2026-10-22）

| 阶段 | 点击到面板可见 | 其中"取数据"耗时 |
|---|---|---|
| 改前（每次点击全量串行 AX 扫描，主线程） | ≈ 2.9s | 2800ms |
| 第一版（并行遍历 + 异步巡检 + 图标缓存） | 285ms | 264ms |
| **最终版（启动时缓存 + 点击只做差集）** | **18ms** | **5–8ms** |

核心原则：**启动/排布时已经扫过一遍，点击时不该重扫**。点击只做差集：

1. `NSWorkspace.runningApplications` 取当前 App 集合（一次系统调用，几毫秒）。
2. 缓存里丢掉 pid 已消失的项（App 被退出）。
3. 只对"从没扫过的 pid"补扫（真正新开的 App，通常 0 个；有也就 1 个，并行扫）；
   这里必须记"扫过但没有菜单栏项"的 pid 集合，否则每次都会把没项儿的 App 当新的重扫一遍。
4. 合并 + 按 x 排序，写回缓存。

实测（退出/重开 Moom 验证差异逻辑）：

```
Moom 在跑 → 点开：20 项，扫描 6ms，总 18ms
退出 Moom → 点开：19 项，扫描 5ms，总 17ms
重开 Moom → 点开：20 项，扫描 6ms，总 19ms
```

配套两个改动：
- **并行遍历** `scanApps()`：`DispatchQueue.concurrentPerform` 一个 App 一个线程，
  每个 App 独立 `AXUIElementCreateApplication` + 0.25s 超时（子元素也必须设，
  否则 `frame()`/`actions()` 退回 6 秒默认值）。全量扫描从"所有超时相加"变成"最慢的那一个"。
- **异步巡检**：每 2 秒的自适应检查在后台队列跑，扫完回主线程只做判断，不与点击抢主线程。
- **map 缓存** `IconCache`：以 bundle id 为键缓存图标，排布结束时后台预热，点击时零查询。

边界：缓存为空（进程刚起来、还没扫过）时自动退回全量并行扫描（约 285ms）。
