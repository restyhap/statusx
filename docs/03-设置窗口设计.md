### 2.3 应用（替代原「双栏拖拽」方案）

一个列表，**每行一个 App**，行内三个元素：

```
[✓]  (图标)  App 名称                                [↑] [↓]
```

- 复选框 = 该 App 的图标是否显示在菜单栏上（勾选写进 `pinnedBundleIDs`，即"始终保留"）。
  未勾选 = 该 App 会被折进 `<<`（撑满模式下就是全部不勾）。
- `↑` / `↓` = 调整该 App 在菜单栏上的左右顺序，**只有勾选的项可以调整**，
  顺序写进 `savedOrder`，由 ⌘-拖拽落地，重启后自动还原（记忆功能）。
- 列表排序展示：先列已勾选的（按当前顺序），再列未勾选的（按名称）。
- 数据来源：当前所有有菜单栏项的 App（`MBar` 扫描结果）。
- 顶部说明一行：`勾选 = 图标留在菜单栏；顺序用 ↑ ↓ 调整，会记住。`

## 7. 已确认的决策（2026-10-23）

1. **应用图标显示**：做成设置里的一个小选项（勾选列表），**不做拖拽交互**。
2. **应用排序**：在同一个小选项里用 `↑` `↓` 调整，带记忆（写入 `savedOrder`，启动还原）。
3. **面板宽度**：不做固定值，做成可调选项；内容显示逻辑后续再完善。

## 8. 布局骨架（2026-10-23 定稿，后续分页复用）

结构对应 HTML 的 `ul > li > button`：

```
窗口
├── 左栏容器（固定宽 128pt，左对齐）
│   └── 竖排按钮列表（每个按钮 = 一个 li，等宽撑满左栏 − 左右各 10pt）
├── 分割线（1px，距窗口上下各 12pt）
└── 右栏（滚动区，四边距 16/18/20/16，内容铺满）
```

实现约束（缺一不可，否则会出现"按钮只有文字宽"或"内容被挤到右边"）：

1. 左栏用一个固定宽度的容器视图承载，宽度只在一处定义（`sideWidth = 128`）。
2. 按钮列表 `alignment = .width` + `distribution = .fill`，并给每个按钮加
   `widthAnchor == 列表宽度`：只靠 stack 的 alignment 会出现按钮退回内容宽度。
3. 右栏不再套 `NSStackView` 装页面（`pane.width == content.width` 会形成循环约束，
   内容块被推到右侧，表现为"左中右三栏"）。现在把页面视图直接铺满滚动文档视图。
4. 页面内部用行式布局 `pane(rows:)`：每行 `leading/trailing` 都贴住页面，
   行宽天然一致，不会再出现某一行缩进。
5. 说明文字必须在视图进入窗口后再设 `preferredMaxLayoutWidth`；
   提前给没有共同祖先的视图加约束会抛 `NSException` 直接崩溃。

### 8.1 左栏按钮（`SidebarButton`）

不要用 `NSButton` 自带的 `image` / `title`，原因有两条（均已实测）：

- 自带 `image` 的画布大小随 SF Symbol 变化，`menubar.rectangle` 比 `square.grid.2x2`
  看着更大；而且没法控制图标与文字的间距。
- 程序化创建（`init(frame:)`）的 `NSButton` 标题默认是 `Button`，会和自绘文字叠在一起，
  表现为文字重影、"通用on"这种怪画面。清理时要同时清 `title`、`alternateTitle`、
  `attributedTitle`、`cell.title` 四处。

定稿做法：`SidebarButton : NSButton`，内部固定两条约束——

- 图标：`NSImageView` 固定 `16×16` 槽位，符号统一 `SymbolConfiguration(pointSize: 13, weight: .regular)`，
  `imageScaling = .scaleProportionallyDown`，左距 10pt，垂直居中；
- 文字：`NSTextField(labelWithString:)`，13pt，`leading = iconView.trailing + 8`（固定间隔）；
- 点击：重写 `hitTest` 把子视图命中都归给按钮本身，整行可点；
- 选中态：`setSelected(_:)` 统一改底色（白 0.5 / 12% 圆角 6）、字重（semibold）、
  文字与图标颜色（`labelColor` / `secondaryLabelColor`）。

### 8.2 行（`pane(rows:)` 里的每一行）

- 分节标题：13pt 加粗，单独一行，上下由 `gapRow(12)` 拉开
- 键值行 `row(title:control:)`：标签 12pt **左对齐、固定 88pt 宽**，控件紧跟其后 10pt，
  行尾用 `sxSpacer()` 吃掉剩余宽度（标签右对齐会让每行控件起始位置飘）
- 复选框行 `toggleRow`：整行可点，文字贴左，最小高度 22
- 按钮行 `buttonRow`：靠左排，按钮之间 8pt，不居中、不拉满
- 说明行 `noteRow`：11pt 次要色，按页面宽度折行

## 9. 通用页（2026-10-23 定稿）

三项，分三节，行式布局：

| 节 | 行 | 控件 | 写回字段 |
|---|---|---|---|
| 启动 | 开机自启动 | 复选框（真实状态取自 `SMAppService`） | `launchAtLogin` |
| 语言 | 语言选择 | 下拉（9 种语言，用各自母语显示，不含日语） | `language` |
| 窗口 | 关闭时操作 | 分段控件：最小化 / 退出 | `closeAction` |

底部一行说明：修改立即生效，不需要确定按钮。

### 9.1 关闭时操作的含义

作用于**关闭设置窗口**（红色按钮 / ⌘W）这一动作：

- `minimize`（默认）：只关窗，StatusX 继续守在菜单栏，可再次从面板「偏好设置」打开。
- `quit`：直接退出 StatusX。

实现：`SettingsWindowController` 作 `NSWindowDelegate`，在 `windowWillClose` 里读
`config.closeAction`；退出前用 `quittingFromClose` 去重（`terminate` 会再关一次窗口，
否则日志会重复触发）。

### 9.2 i18n 实现

- `L10n.swift`：`AppLang`（en / zh-Hans / zh-Hant / ko / de / fr / es / pt / ru）+ `L10n.pick([9 种译文])`。
  每条文案写成一行 9 个值，按 `AppLang.allCases` 顺序取列，缺列回退英文。
- `Str` 里全是计算属性，**取值时才读当前语言**，所以切语言后重建界面即可，不用重启。
- 语言来源：`config.language`，不写则跟随系统（`AppLang.detect()`）。
- 切换语言：`update()` 写配置后 `DispatchQueue.main.async` 重建整个窗口（左栏 + 当前页 + 标题），
  面板由 `AppController` 的 probe key 里带上 `L10n.lang` 触发重建。
- 面板（弹出窗）的标题栏、统计卡片、列表文案同样走 `Str`，切语言后下一次点开就是新语言。

### 9.3 多语言下的宽度规则

中文最短，德语/俄语明显更长，写死宽度会截断（实测俄语「Приложения」「О программе」被切）：

- 左栏宽度：`max(128, 最长的分页名宽度 + 10 + 16 + 8 + 24)`；
- 键值行标签列：`max(88, 最长标签宽度 + 8)`，整列对齐不随行变化；
- 说明文字必须用 `NSTextField(wrappingLabelWithString:)`：`labelWithString` 的 cell 是单行模式，
  英文/德文长句会横向撑出窗口（实测）。

## 10. 菜单栏「图标带」（2026-10-26 重做）

### 10.1 结构

StatusX 在菜单栏里不再只是一个小图标，而是一条**连续的图标带**：

```
[ StatusX 标识 ][ 应用1 ][ 应用2 ] ... [ 空白 ][ 系统项 ]
└──────────── 一条 NSStatusItem，整段可点 ────────────┘
```

- 标识 22pt，应用图标 20×20（等比缩放居中），间隔 2pt，左右留白 7pt（`BarStrip` 常量）。
- 应用图标用原色绘制，标识用 `SymbolConfiguration(paletteColors:)` 上色（深浅由壁纸顶部亮度决定）。
- 带子的总宽 = 菜单栏可用宽度（`fillToMax`），加图标只是让**空白变短**。
  关掉 `fillToMax` 时带子只占内容宽，随图标增减自动变。

### 10.2 排序与刷新

- 排序只改 `pinnedBundleIDs` 的顺序 → `renderStrip` 立刻重画。
- `AppController.applyConfig` 里做了判断：**同一批图标只是换了顺序**时只重画、不重排（`图标顺序变化 → 只重画，不重排`）。
- 增删图标会改变内容宽，才需要一次宽度重排。
- 全程不使用合成鼠标去拖任何别人的菜单栏项。

### 10.3 点击分流

- 点应用图标 → `NSRunningApplication.activate` 切过去（没运行就 `NSWorkspace.openApplication`）。
- 点标识或空白 → 弹状态面板（原有 `togglePanel`）。
- 命中判定用 `NSEvent.mouseLocation.x - button.window.frame.minX` 对齐带子坐标；
  状态项按钮的 `convert(from: nil)` 在菜单栏里恒返回中点，不能用（实测）。

### 10.4 视图层实现要点（踩坑记录）

| 现象 | 原因 | 做法 |
|---|---|---|
| 状态项整段点不动 | 按钮图宽 = 状态项宽 | 图只画内容宽 |
| 图标组跑到中间 | `imagePosition = .imageLeft` 对独图无效 | `StripHostView`（`hitTest` 返回 nil）贴左 |
| 标识成黑块 | 模板图 `draw` 不吃 `NSColor.set()` | palette 配置上色 |
| 深浅判断乱跳 | 按钮 `effectiveAppearance` 随挪位/变宽变化 | 量壁纸顶部 3% 平均亮度 |

### 10.5 仍然保留的一次自我挪位

排布开始时会把 StatusX **自己**挪到菜单栏最右端（`DragSynth.move`）：菜单栏右对齐，
只有站在最右端，变宽才会把左边的项收进 `<<`。只移动自己，不动别人的图标，也不参与排序。

## 10. 状态组件页（2026-10-30 实现）

六个组件排成**一行胶囊按钮**（不是一列），按钮有三种状态：

| 状态 | 外观 | 行为 |
|---|---|---|
| 选中 | 强调色实心 + 白字 | 写进 `metrics`，带子里显示 |
| 未选中 | 浅灰底 + 主色字 | 从 `metrics` 移除，带子不显示 |
| 禁用 | 更淡的灰 + 三级字 | 本机读不到数据时置灰、点击无反应，下面补一行原因 |

| 组件 | 写回字段 | 说明 |
|---|---|---|
| CPU / 内存 / 网络 / 硬盘 | `metrics` | 网络图标跟随接口（Wi-Fi / 有线 / 蜂窝 5G·4G·3G）；硬盘是启动卷已用比例 |

| 显示数值（单独一行） | `metricValues` | 关掉后带子里只剩图标 + 名称 |
| 自动宽度（单独一行） | `autoWidth` | 打开（默认）时把 310 的剩余空间均分到组件之间，内容铺满整条带子；关掉则紧凑左对齐 |

- **可用性是同一份判断**：`Metrics.availability()` 同时供设置页与带子使用（`MetricSnapshot.available`），
  不会出现「设置里禁用、栏上还在显示」。读不到时：设置里置灰 + 说明，带子里直接不画。
- 读不到的原因文案：风扇「SMC 不可用」，电池「本机没有可读电池」。

页面底部两条说明：网络图标来源（蜂窝按速率估算，不是真实制式）、风扇读取方式（无公开 API，走 SMC）。

- `metrics` 存成固定顺序 `cpu,memory,network,disk,battery,fan`，与带子里的显示顺序一致；不写这个键 = 六个都显示。
- 改任一开关立刻重画带子（不重启、不重排菜单栏）。
- 六个全关时停止采集定时器（2s 一次），带子变成一条空白可点区域。

### 10.1 带子的画法（2026-10-30 改版）

- 不画 StatusX 自己的标识，整条带子都可点开面板。
- 每个组件分左右两列：
  - **左列**：一个 **11.5pt 的正方形图标槽**在上，名称（7pt、78% 不透明度）贴底、水平居中，
    图标与名称间距 0.8pt（图标顶部留 2pt；再往下会被状态项 22pt 的边界裁掉）

    每行在这个插槽里**左右居中**（两行的网络 `↑2.6k` / `↓512` 会以较长的一行为准居中）
    （网络的上下行都有流量时用两行，只有单向流量时退回一行）
- 图标在方槽里上下左右居中；上下方向按**墨迹重心**校正（±0.6pt 内），因为 wifi 的弧在上、硬盘的体在下，
  只按包围盒居中会看着偏。
- **图标统一按「墨迹高度 10pt」对齐**，宽度按各自比例（上限 15pt）。各套 Iconify 图标留白差别很大
  （实测墨迹 bbox 占画布 0.59–0.93：电池 0.59、风扇 0.86、cell-5g 0.93），只按「同尺寸」画会一个显大一个显小。

  其余图标保持 10pt；所有图标底部对齐同一基线。
- **所有组件的左列取同一宽度**（取「最宽图标」和「最长名称」中的较大者），图标与名称都在这列里居中，
  因此图标中心线、名称基线全部对齐。
- 组件间距 5pt（放不下降到 4 / 3），仍放不下才从末尾裁组件（310 是硬上限）。
- 关掉「显示数值」时只留左列（图标 + 名称）。
- 插电时电池没有数值，只显示图标 + 「电池」。
- 图标是随包 SVG，按菜单栏明暗把 `currentColor` 换成白/黑再解析（`isTemplate` 对 `_NSSVGImageRep` 无效）。

### 10.2 宽度跟随组件数量（2026-11-02 定案）

```
预留宽度 = Σ(每个组件「最宽可能值」的宽度) + 间距 + 左右留白
带宽     = clamp(预留宽度, 一个组件的宽度, 310)
```

- 只有 2 个组件时整条只有 ~112pt，不占满 310；六个全开时预留 326 → 封顶 310。
- 用「最宽可能值」而不是当前值：数值从 9% 变 100% 时宽度不动。
- 宽度变了才写 `statusItem.length`（差 > 1pt），内部再按等宽格子把内容排匀。
- 关掉「自动宽度」→ 固定 310。

### 13.5 进程行的 ✕ 为什么点不动（2026-11-04）

原因：退出按钮依赖 `ClickProxy.shared.handlers[ObjectIdentifier(button)]` 这张映射表，
面板每次重建都会 `handlers.removeAll()`；行被放进卡片内的小滚动区后重建顺序变化，
屏幕上的按钮和表里登记的按钮对不上，点下去就查不到回调。

改成**自包含按钮** `ActionButton`：按钮自己持有闭包、target/action 指向自身，
不再依赖外部映射表。实测点 ✕ 输出 `点退出：idea pid=24940 找到应用=true 结果=true`。

### 13.6 滚动条不压 ✕（2026-11-04）

正好压住 ✕。修法：列表内容右侧留 14pt 空白（`stack.width = 文档宽 − 14`），✕ 因此退到滚动条左侧。

### 13.7 进程 ✕ 真正退出（2026-11-04）

`NSRunningApplication(pid).terminate()` 只对 **GUI App** 有效；面板里很多行是命令行/守护进程
（`opencode.exe`、`MenuBarAgent` 等），`NSRunningApplication` 直接返回 nil，`terminate?()` 静默失败。

现在 `Panel.quit(pid:name:)` 两级处理：

```swift
if let app = NSRunningApplication(processIdentifier: pid), app.terminate() { 成功 }
else if kill(pid, SIGTERM) == 0 { 成功 }
```

同时进程排行里排除自己的 pid，避免点 ✕ 把 StatusX 自己结束掉。
实测：对一个 `sleep 300` 子进程执行同一逻辑 → `SIGTERM`，进程状态 15（被终止）。

### 13.8 系统进程不显示 ✕（2026-11-05）

进程行是否显示退出按钮，由采样时的 `canQuit` 决定：

| 判定 | 结果 |
|---|---|
| pid ≤ 1 / 在黑名单（launchd、WindowServer、loginwindow、Finder、Dock…） | 不显示 |
| `proc_pidinfo(PROC_PIDTBSDINFO)` 的 uid ≠ 当前用户（root / 其它用户） | 不显示 |
| 可执行路径在 `/System/`、`/usr/sbin/`、`/usr/libexec/`、`/sbin/`、`/usr/bin/` | 不显示 |
| 其余（当前用户自己的 App / 命令行） | 显示 ✕ |

即使显示，点击也会再做一次「pid>1、不在黑名单、进程名复核」才真正发信号。

### 13.9 按应用统计、整应用退出、无按钮也对齐（2026-11-05）

- **统计口径从「进程」改成「应用」**：`proc_pidpath` 里含 `.app/` 的，按 App 归并
  （`Cumora.app/Contents/Helpers/Renderer` → `Cumora`），CPU 与内存按 App 内所有进程求和；
  不在 .app 里的按可执行文件名归并（`opencode.exe`、`mysqld`）。
- **退出 = 关掉该应用的全部进程**：`Panel.quit(pids:name:)` 逐个走「优雅退出 → SIGTERM」，
  最后汇总成「已退出（N 个进程）」/「拒绝：系统进程」等结果，并弹提示。
- **对齐**：没有 ✕ 的行（系统进程）放一个 18pt 等宽空白占位，百分比列与其它行对齐。

### 13.10 为什么 mysqld 点 ✕ 关不掉（2026-11-05）

`mysqld` 是 **brew services 托管的 launchd 服务**：

```
brew services list → mysql@8.4 started  resty  ~/Library/LaunchAgents/homebrew.mxcl.mysql@8.4.plist
```

- 杀进程后 launchd 会立刻把它重新拉起（日志里 pid 90606 → 96569 就是这个过程）；
- 面板数据是 2 秒前采样的，点击时旧 pid 已经不存在，身份复核（`proc_name` 比对）判定「进程已变化」，
  于是取消操作——之前的提示把原因吞成了「失败：1 个进程未能结束」。

现在：
- 失败提示会**带上真实原因**（如「进程已变化（现在是 mysqld），已取消」）；
- 成功结束 0.6 秒后会复查同名进程，若被拉起就再弹一条：
  `mysqld 已被重新拉起（服务类进程，需用 brew services 停止）`。

真正停止服务：`brew services stop mysql@8.4`（或 `launchctl bootout gui/$UID/homebrew.mxcl.mysql@8.4`）。

### 13.11 服务型进程：✕ 改为停服务（2026-11-05）

`mysqld`、`redis`、`nginx` 这类由 launchd 托管的进程，杀进程只会被重新拉起。现在 ✕ 会先识别：

```
launchctl list            →  pid ↔ label（用户域，如 99199 → homebrew.mxcl.mysql@8.4）
launchctl print system    →  系统域服务的 pid
沿进程祖先链（最多 6 层）匹配，命中即为服务
```

命中后弹确认框：「停止服务 homebrew.mxcl.mysql@8.4？」→ 确认则 `launchctl bootout gui/501/<label>`；
系统域服务需要管理员权限，会返回 launchctl 的错误原文。

- 不再用 plist 的 `Program` 路径匹配：很多 plist 写的是 `/bin/bash`（例如 WeChat 那个），会把所有 bash 进程误判成服务。
- 判定改为问 launchd 自己要 pid。

### 13.12 停服务后为什么还看得到（2026-11-05）

`launchctl bootout` 只**卸载 job**：job 的子孙进程（mysqld 就是 mysqld_safe 的子进程）不会跟着退出，
而是被 launchd 收养成孤儿（`ps` 里 PPID=1），继续跑在内存里。

现在点击 ✕ 的完整链路：

1. 弹确认 → `launchctl bootout gui/<uid>/<label>`（卸载 job，不再自动拉起）；
2. 立刻对这批 pid 补一次 `terminate → SIGTERM`（清理孤儿进程）；
3. **2.5 秒后复查**同名进程：`xxx 已退出` / `xxx 仍在运行（可能正在关闭）`。

`mysqld` 收到 SIGTERM 要刷盘，实测约 3–4 秒才真正退出，所以提示会晚一步给结论。

### 13.13 提示条不撑开面板、CPU/内存同一套逻辑（2026-11-05）

- 提示条改为**固定宽度**（面板宽 − 28）＋ 最多 3 行折行，长文本（如「QQ：已退出 6 个，其余 1 个未处理」）不会再超出圆角背景。
- CPU 与内存两张卡的 ✕ 走的是同一个 `appRow`，行为一致。之前看起来不一致，是因为

### 13.15 面板里的滚动为什么失效（2026-11-06）

三个原因叠在一起：

1. **只放了 5 行**：`ListBox` 重构时把 `topCPU.prefix(5)` 当成了全部数据，文档高度 = 可视高度，自然滚不动。
   现在 20 行都进文档，卡片只露 5 行。
2. **面板会自己消失**：`NSPanel` 默认 `hidesOnDeactivate = true`，而 StatusX 是没有 Dock 图标的 accessory App，
   一失活面板就被藏起来（表现为「打开几秒后不见了」）。已设为 `false`。
3. **`super.scrollWheel` 在这个面板里不生效**：事件能收到（`dy≠0` 已确认），但 `contentView.bounds` 不动。
   改为 `ListScrollView` 自己算偏移：

   ```swift
   let step = event.hasPreciseScrollingDeltas ? deltaY : deltaY * 12
   contentView.scroll(to: NSPoint(x: 0, y: clamp(y - step)))
   ```

实测：滚轮下滚后列表从 `opencode.exe…` 切到 `Cumora / QQ / corespeechd / Sidebar / TrackpadX`，右侧滚动条可见且不压 ✕。

### 13.17 StatusX 自身是否出现在排行里（2026-11-06）
