# StatusX

macOS 菜单栏状态工具：用**一条自己的状态项**显示系统指标（CPU / GPU / 内存 / 网络 / 硬盘 / 电池 / 风扇），
点一下展开详细面板。不搬动、不排序任何其它应用的图标——顺序完全交给系统和你自己的 ⌘-拖拽。

- 带宽自适应：最少一个组件宽，最多 310pt
- 组件可配：显示图标 / 文字 / 图表，数值项可多选、可拖动排序
- 面板实时：卡片 2 秒刷新，进程排行可滚动、可一键退出应用或停止 launchd 服务

---

## 一、状态栏这条带子

### 1.1 布局

每个组件 = **左侧（图标 + 名称）** + **右侧数值插槽**：

```
┌──────────────┬──────────────┬──────────────┐
│  [icon]      │  [icon]      │  [icon]      │     图标 11pt，放进 11.5pt 正方形槽
│   CPU        │   内存       │   网络       │     名称 7pt
│        42%   │        63%   │     ↓1.2M    │     数值 10pt（两行时 8.5pt）
└──────────────┴──────────────┴──────────────┘
```

- 图标按**墨迹高度**对齐视觉大小（实测各图标墨迹占画布 0.59–0.93），CPU 单独放大到 11.2pt；
- 数值插槽：一行垂直居中，两行上下排、每行在插槽里左右居中；
- 组件按**等宽格子**排布，中心点间距恒定，显示 1 个或 6 个都均匀。

### 1.2 带宽规则

```
预留宽度 = Σ(每个组件「最宽可能值」的宽度) + 间距 + 左右留白
带宽     = clamp(预留宽度, 一个组件的宽度, 310)
```

- 用「最宽可能值」（`100%` / `↓9.9M` / `9.9k` / `99.99` / `99:59`）预留，数值跳动不会带着状态项伸缩；
- 宽度变化超过 1pt 才写 `statusItem.length`，改完会重新挂按钮回调（系统改长度会重建按钮）。

### 1.3 可用性

- 电池：读不到就不显示；风扇：**SMC 键读得到就算可用**，0 转只是不画（不再「一会可用一会禁用」）；
- 同一个判断（`MetricSnapshot.available`）同时供设置页与带子使用，不会出现「设置里禁用、栏上还在显示」。

## 二、点击后的面板

### 2.1 卡片

按启用的组件逐张出卡，每张卡结构一致：

```
标题                     右侧数值
▓▓▓▓▓▓▓░░░              4pt 占比条
──────────────────────────────
首列贴左     中间居中     末列贴右
──────────────────────────────
（进程排行 / 其它卷）
```

- CPU：占比 + 迷你曲线 + 系统/用户/Nice/温度 + 进程排行
- 内存：用量/空闲 + 已缓存/App/联动/被压缩 + 进程排行
- 网络 / 硬盘 / 电池 / 风扇 / GPU：对应指标
- 电池卡额外显示 循环 / 设计容量 / 真实容量（`AppleSmartBattery.BatteryData`）与健康度

### 2.2 进程排行机制（重点）

面板里的进程列表不是「随手取几个」，而是有一套固定流程：

| 步骤 | 做法 | 说明 |
|---|---|---|
| 1. 枚举 | `proc_listallpids` | 一次拿到全部进程（本机实测 1100+ 个） |
| 2. 采样 | `proc_pid_rusage(RUSAGE_INFO_V2)` | 每个进程取 CPU 时间与 `ri_phys_footprint` |
| 3. 单位换算 | `mach_timebase_info` | `ri_user_time` 是 mach 时间戳（约 24MHz），不是纳秒 |
| 4. 归一 | ÷ `activeProcessorCount` | 和顶部「系统/用户」统一为「占全部核心」 |
| 5. 按应用聚合 | 路径里的 `.app/` | `Cumora.app/Contents/Helpers/Renderer` → `Cumora`，CPU/内存求和 |
| 6. 排序取前 20 | CPU、内存各一份 | 面板只显示前 5，其余在卡片内滚动 |
| 7. 权限过滤 | `proc_pidinfo(PROC_PIDTBSDINFO)` 的 uid | 不是当前用户的进程不进「可退出」集合 |

几个必须写清楚的细节：

- **只统计可读进程**：本机 1100+ 个进程里约 780 个能读到 rusage，其余属于别的用户，直接跳过；
- **按应用而不是按进程**：所以 `QQ`、`Cumora` 只有一个条目，而不是主进程 + 一堆 Helper；
- **前 20 进数据、前 5 进界面**：卡片可视区只放 5 行，剩下的在这个卡片自己的滚动区里滚
  （滚动条停在右侧 15pt 留白里，不压 ✕）；
- **枚举只在面板可见时跑**：`proc_listallpids + rusage` 约 10–18ms，没必要每 2 秒都跑。

### 2.3 退出 / 停止

- 行尾 ✕：GUI App 走 `NSRunningApplication.terminate()`，命令行/守护进程退回 `SIGTERM`；
- **系统进程不显示 ✕**（uid 不是当前用户、路径在 `/System` `/usr/sbin` `/usr/libexec`、或名字在黑名单如 `launchd`、`WindowServer`）；
- **launchd 服务**（mysqld、redis、nginx…）先识别再确认：`launchctl list` 取「pid ↔ label」，
  沿祖先链匹配（服务主进程往往是 bash / mysqld_safe），确认后 `launchctl bootout`，
  再补 SIGTERM 清理孤儿进程，2.5 秒后复查是否真的退出；
- 点击结果会以提示条反馈（固定宽度、最多 3 行，不撑开面板），同一份内容写进日志。

## 三、设置

| 页面 | 内容 |
|---|---|
| 通用 | 开机启动、语言（9 种，不含日语）、关闭窗口行为、**外观**（面板背景 / 面板宽度） |
| 状态组件 | 六个组件胶囊（可拖动换序，顺序即带子顺序）、显示数值、自动宽度 |
| 状态面板 | 组件显示项：显示图标 / 文字 / 图表；数值项点选添加、拖动排序（最多 2 项进带子） |
| 关于 | 配置路径、日志路径、文档目录、退出 |

## 四、构建与运行

```bash
./scripts/build-app.sh          # 生成 build/StatusX.app
open build/StatusX.app          # 首次启动需授权：系统设置 → 隐私与安全性 → 辅助功能
```

开发时直接跑：

```bash
swift build -c release && .build/release/StatusX   # 继承终端的辅助功能权限
```

- 配置文件：`~/Library/Application Support/StatusX/config.json`
- 运行日志：`/tmp/statusx.log`（带宽、落位、可用性变化、点击结果都会写进去）
- 调试开关：`STATUSX_DEBUG_ICONBOX=1`（画图标方槽）、`STATUSX_OPEN_PANEL=1`（启动即开面板）、
  `SX_OPEN_SETTINGS=1`、`SX_SETTINGS_PAGE=widget|panel|general`、`STATUSX_UNAVAILABLE=fan`、
  `STATUSX_PROFILE=1`（打印每轮采样耗时）

## 五、性能

| 场景 | CPU | 常驻内存 |
|---|---|---|
| 面板关闭 | 0.5–0.8% | 68–75 MB |
| 面板打开 | 0.6–0.7% | ≈91 MB |

采样周期 2 秒；进程枚举（≈10–18ms）只在面板可见时执行；面板刷新用「就地更新数值」，
结构不变不重建视图（重建一次约 100ms，改后约 4ms）。

## 七、已知边界

- 状态项宽度受菜单栏剩余空间限制：菜单栏被塞满时，系统会把整项收进 `<<`（此时栏上看不到，
  点 `<<` 能看到），这是系统行为，与带宽设置无关；
- 电池的「设计容量 / 真实容量」来自 `AppleSmartBattery.BatteryData`（本机 8694 / 7185 mAh），
  旧版 macOS 或部分机型可能不提供；
- 完全退出由「关于 → 退出 StatusX」完成，面板里的 ✕ 只针对其它进程。
